## 工程约束（每次都必须写进任务单）

1. **资源**：任何时候只运行一个 Python / pytest / 回测进程，不并行，不同时启动多个后台任务；单个进程峰值内存不超过 4GB（超过 3.5GB 就要换更省内存的做法）；使用 DuckDB 时执行 `SET memory_limit='3GB'; SET threads=4; SET temp_directory='cache/duckdb_tmp';`；大数据必须按年或季度分块、按列读取、聚合后落盘再释放；先在小样本上测内存，再外推全量，外推超标就先改成分块方案。
2. 只用 `<python 路径>`，所有 Python 调用加 `-B`；不安装任何新包；配置用 TOML。
3. 只在工作区内写文件；数据来源目录只读，不得在其中创建任何文件（包括 `__pycache__`）；测试里加载来源目录里的代码时保持 `sys.dont_write_bytecode = True`。
4. 不改 `docs/comet/` 下任何文件；不运行 `comet native`；不 `git commit`。
5. 不申请更高权限；遇到权限拒绝，直接原样报告，不要绕路；**不要结束任何不是你自己启动的进程**；不要使用联网搜索工具。
6. 需求不清、数据缺失或与 brief 冲突时，用最保守的做法继续，并在最终回复里明确列出；**不许自己改需求**。
7. 同一个问题试 3 次仍不成功，先停下来换思路（看数据、看报错、简化）。
8. PowerShell 里不要用 `>` 保存文本再读（会变成 UTF-16），用 `Out-File -Encoding utf8` 或让 Python 写文件；不要手写日期、分位数等底层算法，用 pandas / numpy / duckdb 自带功能。
